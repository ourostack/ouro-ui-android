A tree whose confirm sheet would show the person anything other than what is sent is now refused, as core 0.18.1's validator says (ourostack/ouro-ui-core#88).

- **Confirm rows are checked:** `validateTree` compares each confirm-sheet row with the rows the catalog gives for the prepared input. A tree is refused if its sheet:
  - drops or reorders a field, or changes a label;
  - changes a value, or hides the real value in `raw` on a field that isn't an id;
  - binds a row to a different field.

  Only an id field (one with `shownAs`) may show a name, with the sent id beside it. The surface still builds its rows from the catalog and the input.
- **Undeclared inputs are refused:** a button input the catalog's action doesn't declare would be sent with no row on the sheet. Android checks the catalog's own keys, so a key named like a JavaScript prototype member is refused too; core's check lets those through (ourostack/ouro-ui-core#91).
- **The label resolver names only id fields:** every other row shows exactly the value sent.
- **Core 0.18.1:** the pin moved from 0.18.0, by tag and SHA-256.

**Checked on:** CI only. The Robolectric tests run core's claims, the composed cases and the snapshots. The sample's X-ray and its composed card run on an Android 17 (API 37) emulator. The maintainer owns no Android device, so nothing here has run on real hardware yet. If you have a device and something differs, please open an issue.

**Install:** add `maven { url = uri("https://ourostack.github.io/ouro-ui-android/maven") }` to your repositories and `implementation("bot.ouro.ui:ouro-hx:0.2.1")`. The Maven files are also attached below.
